# 0006 — Lee 확인 출처와 복수직무 (2026-10-28)

Lee가 이 대화에서 명시적으로 결정·실행 승인했다. 이전 상대 게시시각 계산 방안은 취소한다.

- 게시 시각은 계산·저장·추정 표시하지 않는다. 지원 결정에 불필요한 게시 시각·계정 종류·AI 콘텐츠 표시 조사에 시간·사용량을 쓰지 않는다. 시스템 created_at은 등록 이력이며 원문 게시 시각이 아니다. Bomunttl의 기존 posted_at 기본값도 사용하지 않고 null로 넣는다.
- Lee가 직접 가져온 원문은 `Lee 확인(원문 Facebook, 작성자 Ngọc Mai)`를 출처로 인정한다. 포스터 원문은 `Lee 제공 포스터에서 옮김`으로 기록한다. 이미지 저장은 선택이며 더 요청하지 않는다. R3의 URL·이미지 없는 승인된 admin 등록을 허용하되 source_text는 계속 필수다. 앱·service_role의 확인 기록/확인된 원문 생성·변경은 거부한다.
- 원문 하나에 여러 직무가 있어도 공고는 하나다. 직무별 급여·시간·조건을 표시하고 자동 재생성 후에도 연결을 보존한다. 상단 급여는 `Theo vị trí — xem chi tiết`; 서로 다른 직무를 합친 숫자 범위는 만들지 않는다. 원문 줄 자체와 표시용 직무 이름을 구분한다.
- `10h - 10h`는 그대로 두고 관리자 확인 대상으로 검사표를 실패시킨다. 임의 보정하지 않는다. 이 검사는 공개 차단 장치와 구별한다.
- 번지가 없는 Ngô Tất Tố - TP. Bắc Ninh은 확인되지 않은 좌표를 만들지 않는다. canonical writer로 unresolved 주소만 등록해 기존 관리자 위치 확정 목록에 넣는다. 실제 상호명+도로 위치가 확인되면 해당 정확도를 표시한다.
- 공식 설명을 직접 대조: 첫 직무 CÔ RỬA BÁT → 9402 Người phụ bếp(설명에 rửa bát 포함), 둘째 CHẠY BÀN → 5131 Bồi bàn. DB의 단일 대표 코드는 첫 직무 9402이며 두 직무가 같은 코드라는 뜻이 아니다. 공통 업종은 am_thuc_do_uong.
- 식사 2끼는 설거지 직무에만 표시한다. 전체 공고의 식사 아이콘을 켜 홀서빙에도 제공된다고 주장하지 않는다.

운영 경로: 정상 migration 두 개와 production_check를 같은 PR로 제출 → 필수 CI → 봇 병합 → migrations-apply. api.github.com 차단 시 Codex는 브랜치 push와 SHA 전달까지만 수행하고 Claude가 PR을 만든다. 문서·로컬 시험 성공을 운영 등록·검사표·연속기록 성공으로 주장하지 않는다.
