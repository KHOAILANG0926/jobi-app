# 결정 0005 — 공고 화면은 도면(숫자)으로 지킨다

- 상태: **제안** (Lee 승인 시 "확정")
- 날짜: 2026-10-18
- 누가 정함: Lee (2026-10-18 대화: "누가 하더라도 도면으로 작업", "절대 건들지 말아야 할 틀", "사진 찍어서 비교하는 건 하면 안 돼", "바로 적용하자")
- 영어판: `docs/decisions/en/0005-job-layout-drawing.md`

## 배경
5개월 동안 공고 화면 틀이 작업자(AI 포함)마다 조금씩 바뀌었다. 틀을 숫자로 정한 기준이 없었고, 화면 사진을 보고 판단했다.

## 결정
1. **도면**: `docs/decisions/drawings/job-layout.json`에 공고 화면의 영역 순서·위치·폭·높이·간격·글자 크기·색을 숫자로 적는다. 기준 공고는 CTY KDA(#4824). 대상: 상세 PC·모바일, 목록 카드 PC·모바일.
2. **검사는 치수 측정**: 기계가 화면 각 영역을 숫자로 재서 도면과 대조한다(허용 ±1px). 사진 비교는 쓰지 않는다.
3. **도면에 없는 영역은 불합격**: 새 구역·새 줄을 끼워 넣어도 걸린다.
4. **빈값**: 값이 없어도 영역 자리를 유지한다. 가짜 값은 넣지 않는다.
5. **공고 공개도 도면 통과가 조건**: 공개된 모든 공고를 등록·OCR 공개 직후와 30분마다 운영 화면에서 잰다. 어긋난 공고는 자동 비공개 + 이슈 기록. 기준 공고(#4824)까지 어긋나면 화면 코드 문제이므로 공고는 숨기지 않고 경고만 한다(사이트 전체가 비는 사고 방지).
6. **도면 변경은 Lee만**: 도면·측정기·도면 검사를 실행하는 파일은 Lee 승인 없이 바꿀 수 없다. 누가 작업하든(Claude·GPT·Gemini·현지 개발자) 같다.
7. **사고 → 시험**: 도면 위반 사례는 측정기 자가시험에 추가한다.

## 지키는 장치
- 코드 변경: 필수 검사 `app-screen`이 PR마다 도면 대조 → 어긋나면 병합 불가.
- 운영 배포 후: 운영 배포 확인(deploy-verify)에서 도면 대조 → 실패 시 빨간불 + 이슈.
- 공고: 도면 게이트(`layout-gate.yml`)가 등록·OCR 직후와 30분마다 공개 공고 전체를 재고, 어긋나면 비공개.
- 잠금(CODEOWNERS, Lee 승인 필수): `docs/decisions/`(도면·측정기 포함), `app-screen-check.yml`, `layout-gate.yml`, `deploy-verify.yml`. 결정 0003의 승인 대상에 이 검사 파일 3개를 추가한다.
- 자가시험(매 실행): #4828 회사명 빈값 사고(상세 급여 4px 당겨짐, 모바일 카드 줄 사라짐), 필수 구역 누락, 로고 칸 축소, 도면에 없는 줄·구역, 카드 이미지 칸 축소.
- 예행연습: 게이트·측정기를 바꾸는 PR마다 공고 1건에 고장을 주입해, 실제로 잡히는지와 실제 DB 트리거로 비공개 전환되는지 확인한 뒤 되돌린다(운영 데이터 변화 없음).

## 남은 한계 (장치 없음)
- 공고가 공개된 뒤 게이트가 잴 때까지 몇 분은 공개 상태다(비공개 공고는 화면이 열리지 않아 공개 전에 잴 수 없음).
- 도면이 재지 않는 세부(예: 아이콘 모양, 글 내용)는 잡지 못한다.
