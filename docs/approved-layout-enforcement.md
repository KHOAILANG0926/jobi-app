# 지시 범위 밖의 틀 변경 차단

2026-10-16 사용자 지시: 기존 틀은 유지하고 지시한 부분만 고친다. 모든 파일 동결 방식은 폐기한다.

## 작업 순서
1. AGENTS.md·CLAUDE.md·구조 기준서의 현재 내용을 확인한다.
2. `docs/work-orders/current.json`에 사용자 지시, 작업 모드, 문서 SHA256, 허용 파일과 정확한 before/after 수정 영역을 기록한다. 데이터 등록이면 data-only이며 화면 변경을 허용하지 않는다.
3. 작업 범위 문서만 먼저 별도 PR로 master에 반영한다. 이 단계에는 앱·검사 코드 변경이 없어야 한다.
4. 구현 PR은 기준 브랜치에 먼저 고정된 작업 범위를 그대로 사용한다. 범위표를 코드와 함께 넓히면 실패한다.
5. 기준 브랜치 검사기가 실제 git 변경을 대조한다. 허용 영역을 적용한 결과와 한 글자라도 다른 추가 변경, 다른 파일 변경, 검사기 변경은 실패한다. 정상적인 지정 영역 버그 수정은 통과한다.
6. 카드 변경 시 이미지 있음/없음/차단 상태의 PC·모바일 영역 geometry를 검사한다. 운영에는 테스트 공고를 넣지 않는다.

## 강제 범위와 한계
- 후보 PR이 검사기를 고치거나 검사를 삭제해도 pull_request_target은 기준 브랜치 검사기를 실행한다. secret/후보 코드 실행 없음.
- 문서 해시는 확인한 문서 버전을 식별한다. AI가 문서를 실제로 이해했는지 증명하는 장치는 아니다.
- 기준은 사전 확정한 작업 범위와 실제 변경의 일치다. AI가 사용자 지시를 거짓으로 기록하는 것까지 자동 판별할 수 있다고 주장하지 않는다. 계획 문서는 검토 가능하게 별도 이력으로 남긴다.
- 기존 전체 파일 해시 잠금(check-approved-layout/approved-layout-lock)은 제거한다.
- 최초 교체는 기존 잠금이 검사기 교체까지 막아 관리자 복구가 필요하다. 브랜치 보호를 임의 해제하거나 실패 검사를 성공으로 위조하지 않는다.
